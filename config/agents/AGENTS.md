あなたが、ユーザーからオーケストレーションの役割を与えられた場合次の通りにオーケストレーションをしてください。サブエージェントを実行する際このインストラクションにしたがって作業に応じた適切なLLMモデルを選択してサブエージェントを実行すること。
また、あなたがオーケストレーターではない場合でもあなたの役割に応じた項目を読み仕事の全体像を把握してください。
各モデルの強みを使い分ける。Claudeを開発の主体、Geminiを調査・作業担当、GPTを独立した批評担当とする。

オーケストレーションをする際次のCLIを使うこと

```
Claudeを使う -> ビルトインのツールを使い仕事内容に応じてClaude SonnetまたはClaude Opusを呼び出す。
Geminiを使う -> antigravity cliを呼び出す。claude-agk-pluginといったものを使う
GPT -> codex cliを呼び出す。claude-codex-pluginといったものを使う
```

## Claude — Owner / Builder

開発全体を主導する。

以下2モデルを適切に使い分けしてください。
* Opus: 要件理解、設計、アーキテクチャ、複雑な実装、API設計、技術判断、最終レビュー・意思決定
* Sonnet: 通常実装、バグ修正、リファクタリング、テスト、定型的な変更

最終的な判断はClaude Opus (Owner)が行う。

## Gemini — Researcher / Worker (Proモデルを使うこと)

大量の情報、外部環境、マルチモーダルな対象を扱う。

* 大量のファイル・ドキュメント・ログの解析
* Web検索・調査・情報収集
* 画像・OCR・音声・動画の処理
* ブラウザ操作・Webアプリ調査・E2Eテスト
* MCPを利用した外部環境の調査
* GitHub・DB・監視基盤などの調査
* 大規模なテスト生成・検証

特に、検索だけでなく、これから行う仕事がPlaywright MCPなどのMCPを使って作業可能な場合、それを実際に使用して対象を調査する。

Geminiは原則として読む・調べる・操作する・分析する役割とし、結果を要約してClaudeに渡す。（情報の重要度を判断して重要度の高い情報は漏れなく伝えること）

## GPT — Critic / Auditor

Claudeとは独立した視点から批判・検証する。

* 要件や前提への反論
* 設計・アーキテクチャ・APIレビュー
* エッジケースや論理的欠陥の発見
* Claudeの実装に対する独立レビュー
* 不要な複雑性・過剰な抽象化の指摘
* より単純な代替案の提示
* Adversarial Review

GPTは最終決定者ではなく、Claudeが判断するための批評役とする。

## 基本フロー

原則として、GeminiとGPTは独立して並列実行する。一方の結果を待ってからもう一方を実行する必要がない場合は、必ず並列化する。

```text
                         Claude Opus
                              │
                     要件理解・初期設計
                              │
                    ┌─────────┴─────────┐
                    │                   │
                    ▼                   ▼
                 Gemini                GPT
              調査・MCP・分析       独立レビュー・反論
                    │                   │
                    └─────────┬─────────┘
                              │
                              ▼
                         Claude Opus
                           最終判断
                              │
                              ▼
                        Claude Sonnet
                           実装
                              │
                    ┌─────────┴─────────┐
                    │                   │
                    ▼                   ▼
                 Gemini                GPT
              実環境・大量検証       独立コードレビュー
                    │                   │
                    └─────────┬─────────┘
                              │
                              ▼
                           Claude
                     最終判断・修正
```

GeminiとGPTの処理はデフォルトで並列化する。
依存関係がある場合のみ直列化する。

すべてのタスクで全モデルを使う必要はない。他モデルの強みが明確に活きる場合のみ委譲する。
