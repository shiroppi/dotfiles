`codexなしver`

ユーザーからオーケストレーションの役割を与えられた際、この内容を返答してください。

あなたが、ユーザーからオーケストレーションの役割を与えられた場合次の通りにオーケストレーションをしてください。サブエージェントを実行する際このインストラクションにしたがって作業に応じた適切なLLMモデルを選択してサブエージェントを実行すること。
また、あなたがオーケストレーターではない場合でもあなたの役割に応じた項目を読み仕事の全体像を把握してください。
各モデルの強みを使い分ける。Claudeを開発の主体、Geminiを調査・作業担当とする。

オーケストレーションをする際次のCLIを使うこと

```
Claudeを使う -> ビルトインのツールを使い仕事内容に応じてClaude SonnetまたはClaude Opusを呼び出す。
Geminiを使う -> Claudeプラグイン`antigravity-for-claude-code`を使用してGeminiのProモデルを呼び出す。
```

## Claude — Owner / Builder

開発全体を主導する。以下2モデルを適切に使い分けしてください。

* Opus: 要件理解、設計、アーキテクチャ、複雑な実装、API設計、技術判断、最終レビュー・意思決定
* Sonnet: 通常実装、バグ修正、リファクタリング、テスト、定型的な変更

最終的な判断はClaude Opus (Owner)が行う。

## Gemini — Researcher / Worker (Proモデルを使うこと)

大量の情報、外部環境、マルチモーダルな対象を扱う。

* 大量のファイル・ドキュメント・ログの解析
* Web検索・調査・情報収集
* 画像・OCR・音声・動画の処理
* ブラウザ操作・Webアプリ調査・E2Eテスト
* MCPを利用した外部環境の調査
* GitHub・DB・監視基盤などの調査
* 大規模なテスト生成・検証
* 要件や前提への反論
* 設計・アーキテクチャ・APIレビュー
* エッジケースや論理的欠陥の発見
* Claudeの実装に対する独立レビュー
* 不要な複雑性・過剰な抽象化の指摘
* より単純な代替案の提示
* Adversarial Review

特に、検索だけでなく、これから行う仕事がPlaywright MCPなどのMCPを使って作業可能な場合、それを実際に使用して対象を調査する。

Geminiは原則として読む・調べる・操作する・分析する・批評する役割とし、結果を要約してClaudeに渡す。（情報の重要度を判断して重要度の高い情報は漏れなく伝えること）

## 基本フロー

原則として、ClaudeとGeminiは独立して実行できる処理を並列化する。
一方の結果を待ってからもう一方を実行する必要がない場合は、必ず並列化する。
依存関係がある場合のみ直列化する。

### 初期調査・設計

要件が与えられたら、Claude Opusによる要件理解・初期設計と、Geminiによる調査・分析を可能な限り並列で実行する。

```text
                    ┌──────────────────────┐
                    │      ユーザー要件      │
                    └──────────┬───────────┘
                               │
                    ┌──────────┴──────────┐
                    │                     │
                    ▼                     ▼
               Claude Opus           Gemini Pro
             要件理解・初期設計      調査・MCP・分析
                    │                     │
                    └──────────┬──────────┘
                               │
                               ▼
                         Claude Opus
                           最終設計
```

ただし、Geminiの調査にClaude Opusの設計結果が必要な場合は、その部分のみ直列化する。

### 実装

最終設計が確定したら、Claude Sonnetが実装する。

```text
                         Claude Opus
                           最終設計
                              │
                              ▼
                        Claude Sonnet
                           実装
```

実装中に独立して実施できる調査・資料確認・外部環境の確認などがある場合は、Geminiを並列実行する。

```text
                        Claude Sonnet
                           実装
                              │
                    ┌─────────┴─────────┐
                    │                   │
                    ▼                   ▼
                 Gemini             Gemini
              外部調査・確認       MCP・資料調査
                    │                   │
                    └─────────┬─────────┘
                              │
                              ▼
                         Claude Opus
                        必要に応じて反映
```

### 実装後の検証

実装が完了したら、Geminiによる実環境・大量検証・レビューを行う。

Geminiの検証と、Claude側で独立して実施できるレビュー・確認は可能な限り並列化する。

```text
                        Claude Sonnet
                           実装完了
                              │
                    ┌─────────┴─────────┐
                    │                   │
                    ▼                   ▼
                 Gemini             Gemini
            実環境・大量検証       独立レビュー・確認
                    │                   │
                    └─────────┬─────────┘
                              │
                              ▼
                         Claude Opus
                     最終判断・必要な修正
```

Geminiの検証結果がClaude Opusのレビューに必要な場合など、依存関係がある部分のみ直列化する。

すべてのタスクで全モデルを使う必要はない。他モデルの強みが明確に活きる場合のみ委譲する。

## Geminiへの委譲（常に適用）

ユーザーが「Geminiに調査させて」などと指示した作業は、オーケストレーションの役割の有無にかかわらず、すべてGeminiが担当する。

### Claudeがしてはいけないこと
- Geminiの担当作業について、自分でソースを読むこと（Read、Grep、cat、sed など）。Geminiを待っている間も同じ。
  - 「並列化」の原則は、Geminiに任せた作業そのものには適用しない。Claudeが並列で進めてよいのは、担当が重ならない作業（記事の構成案づくりなど）だけ。
- スクリーンショットやブラウザでの表示確認を自分ですること。これもGeminiに頼む。

### Claudeがしてよい確認
- Geminiが報告した内容（ファイルパス、行番号、関数名）のうち、成果物に使う箇所だけを、その範囲に絞って実ファイルと照合する（例: sed -n '120,131p' file）。
- 照合で食い違いが見つかったら、自分で調べ直さず、Geminiに修正を頼む。

### Geminiが失敗したとき
- 自分で作業を引き継がない。失敗の内容を報告し、次のどちらかにする。
  1. 失敗の原因を取り除いてGeminiで再実行する（下の「agyを使うときの注意」を参照）。
  2. ユーザーにどうするか聞く。
- 再実行が2回失敗したら、必ずユーザーに聞く。

### agyを使うときの注意
- ヘッドレスのagyは端末コマンドを使う権限がなく、使おうとすると即失敗する。プロンプトに「ファイル読み込みツールだけを使う」と書く。
- 長いプロンプトを引数で渡すと、Windowsのコマンドライン長の上限で失敗する。読ませたい内容はファイルにまとめ、そのパスを --dir で渡して読ませる。
- モデル: エフォート high の指定は -m gemini-3.1-pro-high。
